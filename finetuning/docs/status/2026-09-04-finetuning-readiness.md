# RF-DETR 2XL Fine-Tuning Readiness

## Status

RF-DETR 2XL fine-tuning is partially verified. A three-epoch Byte65
`local_test_adapted` characterization completed, but the clean held-out path is
**not ready for a production run**. This is a review snapshot of completed work,
intended execution, hyperparameters, and open gates. The authoritative plan remains
`finetuning/docs/plans/2026-09-03-rfdetr-2xl-mot20-training.md`.

## Dataset Plan

### Clean Baseline

The initial training mix is the ByteTrack-compatible combination of MOT20
training-sequence `train_half`, CrowdHuman `train`, and CrowdHuman `val`.
MOT20 `val_half` remains the immutable detector-selection split. All sources
are one class: COCO category `1`, RF-DETR class index `0`, `pedestrian`.

CrowdHuman has been extracted to a new explicit local directory and every ODGT
image ID resolves. The generated clean dataset root uses ByteTrack-style linked
source image roots and RF-DETR's required `train`/`valid` annotation layout.
The converter refuses existing output directories and manifest writers refuse
existing files.

### Byte65 Overlay

`datasets/MOT20_TEST_DET_DEEPAK/byte65nms_68seq/` is a separate local,
test-adapted source derived only from `post_modification_annotations/`. It uses
MOT20 test frames from `MOT20-06` and `MOT20-08`; it must not be presented as
held-out MOT20 evidence.

On 2026-09-04, the user confirmed that these labels received an exhaustive human
semantic audit. Byte65 is therefore approved for the separately named
`local_test_adapted` baseline, not for the immutable clean baseline or any
leaderboard-comparable report. Any use must follow `docs/MOTPolicy.md`.

The immutable assembled root
`datasets/finetuning/rfdetr-mot20-crowdhuman-byte65-test-adapted-2026-09-04`
contains 23,859 train images and 1,154,031 annotations, including 21 Byte65
images and 2,588 Byte65 annotations. Its MOT20 `val_half` remains unchanged at
4,463 images and 676,519 annotations. The completed audit found no cross-split
duplicate image bytes or temporal overlap; the maximum loss-participating image
still has 377 labels, so $Q=390$ remains sufficient.

## Hyperparameters

### Fixed Or Approved

| Setting | Value / rule | Status |
| --- | --- | --- |
| Model | `RFDETR2XLarge` through `rfdetr_plus` | smoke-tested |
| Classes | 1 (`pedestrian`) | fixed |
| Image pipeline | Native 1120px short-side aspect-preserving path; loader-side 920--1320px multi-scale; no crop jitter; 40px batch padding | loader-audited |
| Precision | bfloat16 automatic mixed precision | smoke-tested |
| Device | One visible GPU, `device="cuda"` | verified workaround |
| Ignored-region IoU | 0.5 | implemented and synthetic-tested |
| Classification loss | RF-DETR 1.9.4 default IA-BCE; ordinary sigmoid focal mode is supported | integration-tested |
| Query capacity | `num_queries = num_select = eval_max_dets = 390`; published 300-query groups expand with pretrained rows preserved and initialized added rows | real-density and tracer-tested |
| Physical batch / accumulation | 8 / 1 per rank (global 64) | capacity-verified at the audited 1360x1360 envelope; not a full-epoch or upper-limit result |
| Detector evaluation | Retain RF-DETR top-$Q$ outputs before tracker score/NMS selection | approved |
| Tracker tuning | Tune score/NMS and ByteTrack thresholds only on MOT20 `val_half` | approved |

## Review Gates

Do not close readiness or start real fine-tuning until fresh evidence shows:

- A three-epoch clean run passes full held-out evaluation, checkpoint writing,
  and resume validation at the loader-audited 1360x1360 padded envelope.
- Final optimization, schedule, augmentation, and evaluation settings were
  recorded and reviewed.
- The Byte65-including baseline is materialized and audited with the
  user-confirmed exhaustive audit recorded, then reported as local test-adapted
  work.
